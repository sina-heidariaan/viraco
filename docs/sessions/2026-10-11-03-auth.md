# Session 2026-10-11-03 — Auth module (S2)

Goal: Login, refresh, logout and me with HttpOnly cookies, global guards, one error shape.
Milestone: M2

Done:
- Auth module: POST /auth/login, /auth/refresh, /auth/logout, GET /auth/me; refresh tokens rotated and stored as SHA-256 hashes; reuse of a revoked token revokes all of that user's refresh tokens.
- Global AuthGuard (DB user lookup, is_active, token_version) and RolesGuard; @Public, @Roles, @CurrentUser.
- AllExceptionsFilter with the §6.4 shape; validation errors as `details: [{ field, message }]`.
- Login rate limit 5/min/IP (throttler, login route only).
- Fixed a pre-existing S1 bug: COOKIE_SECURE=false was parsed as true.
- Checked by curl against the running API: all four endpoints, rotation, reuse, logout, disabled user → 401, bumped token_version → 401, 6th login → 429.

Decisions:
- Express `trust proxy = loopback`: req.ip comes from X-Forwarded-For set by the Next.js proxy. The proxy (S5) must set that header, or every user shares one rate-limit bucket.
- Logout is public (works with an expired access token); login/refresh return `{ id, email, name, role }`.
- Two parallel refreshes with one token: the second counts as reuse and logs the user out. The S5 client must single-flight refresh (plan §8.5 already says so).
